# Milestone v0.2.0: Windows + DevEx

**Status:** SHIPPED 2026-01-29
**Phases:** 9-12
**Total Plans:** 14

## Overview

Clue v0.2.0 extends the build system with Windows MSVC support as the priority feature, followed by build profiling for diagnostics and watch mode for developer experience. The roadmap progressed from toolchain abstraction (enabling multi-compiler support) through MSVC integration, then added profiling and watch mode as independent capabilities.

## Phases

### Phase 9: Toolchain Abstraction

**Goal**: Compiler-agnostic interface that enables GCC, Clang, and MSVC to share build logic
**Depends on**: Phase 8 (v0.1.0 complete)
**Plans**: 4 plans

Plans:
- [x] 09-01: Create Toolchain interface and GCC/Clang implementations
- [x] 09-02: Update all toolchain consumers to use the new interface
- [x] 09-03: Update all tests to work with the new Toolchain interface
- [x] 09-04: Clean up deprecated code and finalize the refactoring

**Details:**
- 9-method Toolchain interface covers all compiler operations (paths, flags, identity)
- GCC and Clang have different coverage flags (gcov vs source-based coverage)
- Migrated all build components from concrete *Toolchain to Toolchain interface
- Builder uses NewToolchain factory instead of DiscoverToolchain
- Flag generation delegated to toolchain methods (CompilerFlags, LinkerFlags)
- Cache manager accepts pre-computed flags arrays instead of Config struct

### Phase 10: Windows MSVC

**Goal**: Users can build C/C++ projects on Windows using Visual Studio's MSVC toolchain
**Depends on**: Phase 9
**Plans**: 4 plans

Plans:
- [x] 10-01: VS discovery with vswhere.exe and vcvarsall.bat environment capture
- [x] 10-02: MSVCToolchain implementation with flag translation
- [x] 10-03: Linker/compiler updates for link.exe, lib.exe, response files
- [x] 10-04: Comprehensive tests for MSVC toolchain

**Details:**
- vswhere.exe with -latest -products * for broadest VS detection
- vcvarsall.bat environment capture via temp batch script + cmd.exe
- CLUE_MSVC_PATH and CLUE_MSVC_ARCH environment variables for user override
- MSVC flag mapping: none->/Od, size->/O1, fast->/O2, aggressive->/O2
- Response file threshold: 8000 chars (safety margin under Windows 32K limit)
- Static CRT default (/MT release, /MTd debug)
- DLLs automatically generate import library via /IMPLIB:output.lib
- Mock MSVCInstallation enables MSVC tests on Linux

### Phase 11: Build Profiling

**Goal**: Users can identify compilation bottlenecks with timing data and performance summaries
**Depends on**: Phase 9 (uses toolchain interface for timing hooks)
**Plans**: 3 plans

Plans:
- [x] 11-01: Profiler core with timing collection and Chrome Trace export
- [x] 11-02: CLI flags and builder integration for profiling
- [x] 11-03: Comprehensive tests for profiler and Chrome Trace

**Details:**
- Microseconds for Chrome Trace ts/dur fields (spec requirement)
- formatDuration uses adaptive precision: [2.3s] for >= 1s, [450ms] otherwise
- Flag precedence: --profile flag > CLUE_PROFILE env var
- ThreadID derived from completed counter modulo jobs
- --profile flag enables detailed per-file profiling
- --save-profile flag writes profile.json for Chrome Trace visualization
- --top=N flag controls slowest files count (default 10)

### Phase 12: Watch Mode

**Goal**: Users can automatically rebuild when source files change
**Depends on**: Phase 9 (uses toolchain for incremental builds)
**Plans**: 3 plans

Plans:
- [x] 12-01: Watcher core with fsnotify and debounce logic
- [x] 12-02: CLI watch command with screen clearing and status output
- [x] 12-03: Watcher unit tests for filtering and debounce

**Details:**
- 300ms default debounce duration
- All .cue files treated as config changes (not just build.cue)
- Chmod events ignored (only Create/Write/Remove/Rename processed)
- Context cancellation for build interruption on rapid changes
- ANSI escape sequence for screen clearing (\033[H\033[2J)
- WatchCount method for cleaner API
- IsRelevantFile exported for direct unit testing
- HandleEventPath helper enables testing without real fsnotify events

## Milestone Summary

**Key Decisions:**
- Toolchain interface with 9 methods covering all compiler operations
- MSVC support prioritized over MinGW/Clang-cl per research
- fsnotify for watch mode, Chrome Trace format for profiling
- Response file threshold at 8000 chars for safety margin
- 300ms debounce for watch mode per CONTEXT.md guidance

**Issues Resolved:**
- All build consumers migrated from concrete types to interface
- Cache manager decoupled from flag generation logic
- Generate package updated to use toolchain factory
- MSVC tests enabled on Linux via mock installations

**Issues Deferred:**
- MinGW toolchain (deferred to v0.3.0)
- Clang-cl toolchain (deferred to v0.3.0)
- Cross-architecture MSVC compilation (deferred to v0.3.0)

**Technical Debt Incurred:**
- None - all implementations complete with no stubs
