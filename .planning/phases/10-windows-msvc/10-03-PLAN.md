<task type="auto">
  <name>Task 1: Create response file support</name>
  <files>internal/build/response_file.go</files>
  <action>
Create response_file.go with:

1. Constants:
   - ResponseFileThreshold = 8000 (characters, per RESEARCH.md safety margin)

2. WriteResponseFile(args []string) (string, error):
   - Create temp file in os.TempDir() with pattern "clue-*.rsp"
   - Write each argument on its own line (one-per-line format per RESEARCH.md)
   - Return path to response file
   - Caller is responsible for cleanup (defer os.Remove)

3. MaybeUseResponseFile(args []string) ([]string, string, error):
   - Calculate total command line length (sum of arg lengths + spaces)
   - If under ResponseFileThreshold, return args unchanged and empty cleanup path
   - If over threshold:
     - Call WriteResponseFile(args)
     - Return ["@" + rspPath], rspPath, nil
   - Cleanup path returned so caller can defer os.Remove

4. EstimateCommandLength(args []string) int:
   - Sum of len(arg) + 1 for each arg (space separator)
   - Helper for testing and debugging

Note: Response files work for cl.exe, link.exe, and lib.exe with same syntax.
  </action>

Run: go build ./internal/build/
Response file code compiles.
Run: go test ./internal/build/ -run TestResponseFile -v
(Test will be added in plan 04, but verify compilation now.)
  </verify>

Update linker.go to handle MSVC toolchain differences:

1. Add helper function isMSVC(tc Toolchain) bool:

2. Update LinkExecutable:
   For MSVC toolchain:
   - Use link.exe directly (get from PATH via MSVCToolchain environment)
   - Build MSVC-style command: link.exe /nologo objects... /OUT:output.exe libs...
   - Translate library flags: -lpthread -> nothing (Windows has different threading)
   - System libraries use .lib suffix: kernel32.lib, user32.lib
   - Add /DEBUG if debug enabled
   - Use MaybeUseResponseFile for long command lines
   - Show full command line on linker errors (per CONTEXT.md)

   For GCC/Clang (existing logic):
   - Keep existing behavior unchanged

3. Update CreateStaticLibrary:
   For MSVC toolchain:
   - Use lib.exe instead of ar
   - Command: lib.exe /nologo /OUT:output.lib objects...
   - Use MaybeUseResponseFile for many objects

   For GCC/Clang:
   - Keep existing ar crs behavior

4. Update LinkSharedLibrary:
   For MSVC toolchain:
   - Use link.exe with /DLL flag
   - Command: link.exe /nologo /DLL objects... /OUT:output.dll /IMPLIB:output.lib
   - Generate import library (.lib) alongside DLL
   - Use MaybeUseResponseFile for long command lines

   For GCC/Clang:
   - Keep existing -shared behavior

5. Add getMSVCLinkerPath(tc *MSVCToolchain) string helper:
   - Extract link.exe path from MSVCToolchain environment
   - Similar to how CC() returns cl.exe path

6. Add getMSVCLibPath(tc *MSVCToolchain) string helper:
   - Extract lib.exe path from MSVCToolchain environment

Note: Keep existing GCC/Clang code paths unchanged. Use type assertion or Name() check to branch.
