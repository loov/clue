<task type="auto">
  <name>Task 1: Implement dependency resolver</name>
  <files>internal/deps/resolver.go</files>
  <action>
Create resolver using existing graph infrastructure:

1. `Resolver` struct:
   - `dependencies map[string]Dependency`

2. `NewResolver(deps map[string]Dependency) *Resolver`

3. `BuildOrder() ([]string, error)`:
   - Create graph using `dominikbraun/graph`:
     ```go
     g := graph.New(graph.StringHash, graph.PreventCycles())
     ```
   - Add vertex for each dependency
   - For dependencies with their own clue.cue, parse and check for `depends` on other deps
   - Add edges for inter-dependency relationships
   - Call `graph.StableTopologicalSort(g)` for deterministic order
   - Return ordered list of dependency names

4. `ValidateReferences(targets map[string]config.Target) error`:
   - Check that every target's `depends` array only references:
     a. Other targets in the config
     b. Dependencies in the dependencies map
   - Return clear error: "target 'foo' depends on unknown 'bar'"

5. Cycle detection:
   - Graph library handles this with PreventCycles()
   - On cycle error, format message: "circular dependency detected: a -> b -> c -> a"

6. Handle dependencies without interdependencies:
   - Most common case: deps don't depend on each other
   - Return them in alphabetical order for reproducibility

Note: For Phase 6, we don't recursively resolve transitive dependencies. Each dependency's clue.cue can declare deps on other *configured* dependencies, but we don't auto-discover deps of deps.
  </action>
  <verify>go build ./internal/deps/... compiles without errors</verify>
  <done>Resolver determines build order with cycle detection</done>
</task>

<task type="auto">
  <name>Task 2: Implement dependency manager</name>
  <files>internal/deps/manager.go</files>
  <action>
Create manager that coordinates fetch and build:

1. `Manager` struct:
   - `projectDir string`
   - `cache *Cache`
   - `gitFetcher *GitFetcher`
   - `tarballFetcher *TarballFetcher`
   - `vendoredFetcher *VendoredFetcher`
   - `resolver *Resolver`
   - `verbose bool`
   - `ciMode bool`

2. `NewManager(projectDir string, deps map[string]Dependency, opts ManagerOptions) (*Manager, error)`:
   - Initialize cache, fetchers, resolver
   - `ManagerOptions`: verbose, ciMode

3. `FetchAll(ctx context.Context) error`:
   - For each dependency in resolver.BuildOrder():
     - If cache.Has(dep), skip with message "Using cached {name}"
     - Select appropriate fetcher based on dep.Type()
     - Call fetcher.Fetch(ctx, dep, cache.Path(dep))
     - Call cache.MarkFetched(dep)
     - Stop on first error (fail-fast)
   - Return nil if all fetched successfully

4. `FetchOne(ctx context.Context, name string) error`:
   - Fetch single dependency by name
   - Used for `clue deps fetch <name>`

5. `Status() []DepStatus`:
   - Return status of all dependencies:
     ```go
     type DepStatus struct {
         Name     string
         Type     string  // "git", "tarball", "vendored"
         Status   string  // "cached", "missing", "outdated"
         Location string  // Local path
         Ref      string  // For git: branch/tag/commit
     }
     ```
   - "outdated" detection: For git with branch ref, check if local is behind remote (optional for Phase 6)

6. `Clean() error`:
   - Delete entire .deps directory
   - Return cache.Clean()

7. `CleanOne(name string) error`:
   - Delete specific dependency from cache

Progress output:
- "Fetching dependencies..."
- "  [1/3] Cloning libfoo (git:main)"
- "  [2/3] Using cached libbar"
- "  [3/3] Downloading libqux.tar.gz"
- "All dependencies ready"
  </action>
  <verify>go build ./internal/deps/... compiles without errors</verify>
  <done>Manager coordinates fetch operations with progress and caching</done>
</task>
