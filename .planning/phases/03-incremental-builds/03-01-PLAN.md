<feature>
  <name>Cache Key Computation</name>
  <files>internal/build/cache.go, internal/build/cache_test.go</files>
  <behavior>
    CacheKey struct contains:
    - SourceHash: SHA-256 of source file content
    - DepsHash: Combined hash of all header dependencies
    - CompilerID: Compiler path + file mtime + file size (not version parsing)
    - Flags: Normalized compiler flags (sorted, relevant flags only)
    - IncludePaths: Include directories (order preserved)

    ComputeFileHash(path string) -> (string, error)
    - Reads file, returns hex-encoded SHA-256 hash
    - Returns error if file doesn't exist

    ComputeCacheKey(key CacheKey) -> string
    - Combines all fields into single deterministic hash
    - Returns hex-encoded SHA-256 of combined inputs

    NormalizeFlags(flags []string) -> []string
    - Sorts flags alphabetically
    - Filters out display-only flags (--verbose, --color, etc.)
    - Resolves relative paths in -I flags to absolute

    CompilerIdentity struct:
    - Path: string (absolute path to compiler)
    - Mtime: int64 (file modification time as unix timestamp)
    - Size: int64 (file size in bytes)

    GetCompilerIdentity(compilerPath string) -> (CompilerIdentity, error)
    - Stats the compiler binary
    - Returns identity struct for cache key inclusion

    Cases:
    - ComputeFileHash("main.cpp") with content "int main() {}" -> consistent hash
    - ComputeFileHash("nonexistent.cpp") -> error
    - NormalizeFlags(["-O2", "-Wall", "-I./include"]) with cwd /project -> ["-I/project/include", "-O2", "-Wall"]
    - NormalizeFlags(["--verbose", "-O2"]) -> ["-O2"] (verbose filtered)
    - Same CacheKey always produces same ComputeCacheKey result
  </behavior>
  <implementation>
    Use crypto/sha256 from Go standard library (no external dependencies).
    For CompilerIdentity, use os.Stat to get mtime and size.
    For flag normalization, use filepath.Abs for -I paths.
    Filter list for display-only flags: --verbose, --color, --progress, -v
  </implementation>
</feature>

<feature>
  <name>Dependency File Parsing</name>
  <files>internal/build/deps.go, internal/build/deps_test.go</files>
  <behavior>
    DependencyInfo struct:
    - Target: string (the .o file)
    - Sources: []string (source file + all headers)

    ParseDepFile(path string) -> (DependencyInfo, error)
    - Reads .d file content
    - Handles continuation lines (lines ending with \)
    - Extracts target and all dependencies
    - Filters out the target .o file from dependencies
    - Returns error if file doesn't exist or is malformed

    Example .d file content:
    ```
    main.o: src/main.cpp \
      include/config.h \
      include/utils.h

    include/config.h:

    include/utils.h:
    ```

    Cases:
    - ParseDepFile with simple .d -> extracts target and deps correctly
    - ParseDepFile with continuation lines -> handles backslash-newline
    - ParseDepFile with phony targets (from -MP) -> ignores them (empty deps)
    - ParseDepFile on nonexistent file -> returns error
    - ParseDepFile on malformed content -> returns error with context
  </behavior>
  <implementation>
    Read file content, split by lines, join continuation lines.
    Find lines containing ":" and extract target:deps.
    Skip lines where deps list is empty (phony targets from -MP).
    Parse space-separated deps, handle escaped spaces if needed.
  </implementation>
</feature>
