<task type="auto">
  <name>Task 1: Implement Toolchain type and discovery</name>
  <files>internal/build/toolchain.go</files>
  <action>
Create toolchain.go with:

1. Toolchain struct:
   - CC string (C compiler path)
   - CXX string (C++ compiler path)
   - AR string (archiver path)
   - Name string ("clang" or "gcc")

2. DiscoverToolchain(name string, target Platform) (*Toolchain, error):
   - Check CC env var first, fall back to toolchain name
   - Check CXX env var first, fall back to toolchain++ variant
   - For native builds: clang/clang++/ar or gcc/g++/ar
   - For cross-compilation: prefix with GNU triplet (aarch64-linux-gnu-)

3. crossPrefix(target Platform) string:
   - Return GNU triplet prefix for cross-compilation
   - linux-arm64 -> "aarch64-linux-gnu-"
   - linux-amd64 -> "x86_64-linux-gnu-"
   - darwin-* -> "" (macOS cross from Linux deferred to v2)

Import os and os/exec packages.
  </action>
  <verify>go build ./internal/build/...</verify>
  <done>Toolchain struct and DiscoverToolchain compile</done>
</task>

<task type="auto">
  <name>Task 2: Implement toolchain validation</name>
  <files>internal/build/toolchain.go</files>
  <action>
Add to toolchain.go:

1. ValidateToolchain(tc *Toolchain) error:
   - Validate CC via exec.LookPath
   - Validate CXX via exec.LookPath
   - Validate AR via exec.LookPath
   - Return detailed error if any missing: "compiler not found: %s (ensure it is installed and in PATH)"

2. Toolchain.IsCrossCompiler() bool:
   - Return true if CC contains GNU triplet prefix

3. Toolchain.String() string:
   - Return descriptive string for build output: "clang (native)" or "aarch64-linux-gnu-gcc (cross)"
  </action>
  <verify>go build ./internal/build/...</verify>
  <done>ValidateToolchain validates all tools via PATH lookup</done>
